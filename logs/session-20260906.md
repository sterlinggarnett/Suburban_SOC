## Noted, not actioned

`.gitattributes` forces LF for `*.sh`, `*.conf`, `.env*`, `*.cron`, `*.dat` but
NOT `*.service`/`*.timer`. With `core.autocrlf=true` on this host,

## Deviation from the plan

The plan assumed CA plumbing alone made `stack_health.sh` safe under systemd. It
does not: `RuntimeDirectory=` is torn down between `Type=oneshot` runs, so on a
host with no pin-verified cache a Docker-down run leaves no CA at all, and
`es_common.sh` exits 1 — killing the health lane in exactly the outage it exists
to report, taking the container checks and the ntfy push down with the ES ones.
That is #550's failure class rebuilt in the other lane. Added `ES_REQUIRE_CA=0`
(default unchanged at 1) which keeps the *script* alive while still failing
closed on the *wire*.

### What the review pass changed materially

- **The lane no longer authenticates as the `elastic` superuser.** The first
  draft pinned no `ES_USER`, so `es_common.sh`'s default applied and a 5-minute
  timer would have logged in as superuser 288x/day — reversing audit #167/#222.
  New least-privilege `soc_health` user + role (cluster `monitor`, append-only
  `create` on `soc-health`, read-only on `soc-slo-metrics`), provisioned behind
  `SOC_HEALTH_PASSWORD`, credential extracted via the single-secret scratch-file
  pattern from `slo-metrics.service:58`. There was no writer identity for
  `soc-health` anywhere in `configs/elasticsearch/roles/` before this.
- **`soc_admin` could forge `soc-health`.** It holds `all` on `soc-*` and
  already excluded `-soc-slo-metrics`; `soc-health` was left in. One document
  with a current `@timestamp` plus a stopped timer would have kept the SLO lane
  reporting the health lane alive indefinitely. Deletion was already caught via
  `BREACH_IF_NA`; forgery was not caught at all. Excluded now, with the
  `tests/setup/test_soc_admin_role_scope.py` carve-out guard updated
  deliberately rather than as a side effect.
- **A future-dated `@timestamp` read as "fresh" in BOTH halves.** A negative age
  is trivially `<=` any positive threshold, so one forged or clock-skewed
  document pinned either check to healthy forever — the exact failure the pair
  exists to prevent, meaning the headline property did not hold. Both lanes now
  treat a future timestamp past a 120s skew tolerance as the anomaly.
- **`es_common.sh` gated on `[[ -f ]]`, not readability.** A 0-byte `ca.crt`
  therefore took the happy path and the `ES_REQUIRE_CA=0` diagnostic could never
  explain it. Reachable here: `timeout 15 docker cp` killed mid-write leaves a
  truncated file that `es_ca_cache.sh`/`verify_ca_fingerprint.sh` both correctly
  no-op on. Now `[[ -s && -r ]]`.
- **`container_up()` treated name presence as liveness.** `docker ps` lists
  containers in `restarting`, so a crash-looping `soc_ai_agent` read as UP. The
  snapshot now carries `{{.State}}` and only `running` counts.
- **A test failed on this checkout.** The new
  `test_soc_health_within_target_does_not_breach` omitted the `coverage=105.0`
  pin that all ten sibling "does not breach" tests use to clear this repo's own
  `.env SLO_COVERAGE_MIN=35`.
