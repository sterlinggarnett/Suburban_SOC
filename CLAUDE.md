# Blue team analysis conventions
- Never assert an IOC is malicious without a cited source (VT, MISP, internal case).
- If log evidence is ambiguous or incomplete, say so — never guess intent or attribution.
- Map to ATT&CK technique IDs only when clearly evidenced in the provided data.
- Never invent CVEs, hashes, or timestamps — quote verbatim from the source log/report.

- **A PR body with "Closes #X, #Y" (comma-separated, one keyword) does not reliably auto-close both issues** — GitHub sometimes only closes the first. Always verify each referenced issue individually after merging and close stragglers manually (`state: closed, state_reason: completed`). In practice this repo's recent PRs (#505, #506, #507) don't use auto-close keywords at all — every issue on them was closed manually, 15-105s after merge, precisely to avoid relying on the unreliable behavior above. Keep doing that: don't reintroduce `Closes #X`/`Fixes #X` keywords on the assumption they're now safe: the underlying GitHub behavior this note warns about hasn't changed, only this repo's practice of avoiding it. **The parser also ignores negation:** PR #537's squash message said "Does not close #265" and GitHub closed #265 on merge anyway (2026-09-03, reopened by hand). Never write a closing verb directly before an issue number anywhere in a PR title, body or commit message, even negated or quoted — say "leaves #N open" instead.
