## 6. Branch-protection script hardening (after #539 merged)

Owner merged PR #542 and closed #539, then asked for the residual
hardening the security-auditor had flagged. Delivered as a separate PR
(left for the owner to merge — security-control change):

- `required_status_checks` now uses the `checks` form: live entries keep
  their `app_id`, entries the script adds are pinned to GitHub Actions
  (15368), `app_id: null` is never sent.
- Push restrictions, linear history, conversation resolution,
  block_creations, lock_branch and fork-syncing are read from the live
  policy and carried through the full PUT instead of being reset.
- A live review gate is preserved on re-run (`ALLOW_REVIEW_DOWNGRADE=1`
  to remove it); `REQUIRE_REVIEW=1` enables one without lowering a
  stricter live count; flag values are validated, not coerced to off.
- Branch and repo names regex-validated; repo pinned via `GH_REPO`
  (default voltron-1/Suburban_SOC) instead of the cwd remote.
- Post-PUT read-back; any required check missing from it is exit 1, and
  the banner prints the *live* summary; a `deploy_changelog.sh` row is
  appended (SOP-007 evidence). `SKIP_CHANGELOG=1` for tests.
- Second review round (security-auditor re-audit, code-reviewer): push
  restrictions with empty actor lists are preserved (presence-based, not
  count-based — empty lists are a stricter policy, unlike dismissal /
  bypass lists where empty means off); the older `contexts`-only response
  shape is carried forward; an unpinned live check that is one of ours
  gets the Actions pin; the read-back now compares strict, enforce_admins,
  force-push/deletion, review count, restrictions, the carried booleans
  and every pin sent — any drift is exit 1; `GH_REPO` rejects `..` and
  malformed slugs; the changelog hook is exercised in tests.
- `tests/setup/test_setup_branch_protection.py`: the real script under a
  fake `gh` shim, 30 cases (union + pinning, no-op re-run, 404 bootstrap,
  edge response shapes, gate preserve/downgrade/enable, carry-forward,
  fail-closed on non-404, read-back drop and field tamper, bad flags,
  unsafe branch names and repo slugs, changelog hook success/failure).

Not done (org-level, outside the repo): alerting on the audit-log events
