# Blue team analysis conventions
- Never assert an IOC is malicious without a cited source (VT, MISP, internal case).
- If log evidence is ambiguous or incomplete, say so — never guess intent or attribution.
- Map to ATT&CK technique IDs only when clearly evidenced in the provided data.
- Never invent CVEs, hashes, or timestamps — quote verbatim from the source log/report.

- **A PR body with "Closes #X, #Y" (comma-separated, one keyword) does not reliably auto-close both issues** — GitHub sometimes only closes the first. Always verify each referenced issue individually after merging and close stragglers manually (`state: closed, state_reason: completed`). In practice this repo's recent PRs (#505, #506, #507) don't use auto-close keywords at all — every issue on them was closed manually, 15-105s after merge, precisely to avoid relying on the unreliable behavior above. Keep doing that: don't reintroduce `Closes #X`/`Fixes #X` keywords on the assumption they're now safe: the underlying GitHub behavior this note warns about hasn't changed, only this repo's practice of avoiding it. **The parser also ignores negation:** PR #537's squash message said "Does not close #265" and GitHub closed #265 on merge anyway (2026-09-03, reopened by hand). Never write a closing verb directly before an issue number anywhere in a PR title, body or commit message, even negated or quoted — say "leaves #N open" instead.
- **Docker: depends on the session kind.** In a *cloud* session there is no live Docker daemon, Elasticsearch or Kibana — `docker version` succeeds for the client but cannot reach the socket; Docker-dependent work there must be structurally validated only (and disclosed as such) or deferred as environment-blocked, never assumed to pass. **On the local WSL host the situation is different and better: that host IS the capture host** — `zeek-host-capture.service`, `suricata.service`, `filebeat.service` and `intel-refresh.timer` are installed and enabled there, `/storage/PCAP/zeek_logs/` holds the live Zeek output, `/opt/zeek/bin/zeek` is a native 8.0.5 (pre-8.1: no `Log::default_max_*` options) and `/usr/bin/suricata` is 7.0.3 (matches the pin). Docker there comes from Docker Desktop: when the `docker-desktop` WSL distro is Stopped, `docker` is not on PATH at all, `zeek-host-capture.service` crash-loops (`activating`/auto-restart) and the Zeek lane silently stops writing while Suricata and Filebeat stay active — observed 2026-09-04, last Zeek write `Aug 31 20:56`, NRestarts 1305. So before classifying an issue as Docker-blocked locally, check `/mnt/c/Windows/System32/wsl.exe -l -v` and say "start Docker Desktop" rather than "no Docker in this environment". CI's `live-fire` job also has a real Docker daemon and the pinned zeek/zeek image, which is where image-dependent tests actually run (see #389/PR #546's `SOC_REQUIRE_LIVE_ZEEK=1` pattern: a skipped live test shows red there instead of a silent green).
